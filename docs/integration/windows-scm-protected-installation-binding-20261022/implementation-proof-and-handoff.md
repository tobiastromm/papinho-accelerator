## Concrete implementation

The same CLI accepts service install --prepare-lab --installation <absolute-directory> --configuration <relative-leaf>. PS_REQUEST owns bounded copies, rejects traversal/unknown argument shape and keeps default virtual account/no password. Normal service install remains denied; read-only preparation never reaches CreateService. The canonical main passes the existing launcher owner's read-only producer as a synchronous private callback, with a borrowed image handle/identity/hash from the existing SCM owner. This is not another CLI or owner/registry. Parent, configuration, image, operator, token identity and nonce are bound only for that invocation; no receipt survives as effect authority.

server_launcher_scm_prepare_win32.inc executes within the existing launcher root/invocation gate and configuration/pending owner. It reuses personal_native_open/current/close for actual primary operator/token statistics, enabled local administrative/interactive eligibility, held physical parent with OBJ_DONT_REPARSE, parent descriptor snapshot and exact revalidation. Reusing that resource producer does NOT reuse F0–F9 NEW_INSTALL authorization or declare an initial root. No domain/root identity, CURRENT/predecessor/CA or grant is manufactured from a directory ID.

New read-only helpers in server_configuration_personal_native_win32.inc open the executable leaf and configuration leaf RELATIVE to that held parent through the existing NtCreateFile backend (OPEN only, no reparse, non-directory synchronous files, shared-read). The relative image's native volume/file identity, size and timestamp must match the independently held SCM image observation. Source bytes are bounded to8192 and retained in the existing pending next buffer, parsed by the existing .conf parser, hashed by the unchanged qualified capsule and reread/compared byte-exact using the existing pending compare scratch. A path/hash alone never proves ownership. This is file observation, not mapped executable attestation or external clone protection.

The new image handle is explicitly named scm_image in the same native pending context (+8bytes measured). Checked close-attempt bit512 is disjoint from existing child/token/file/LocalFree bits. It closes before the protecting parent; no old bootstrap handle is repurposed. Failed close/free retains the reference and same root; no automatic retry, second pins table, eviction or timeout release. Existing actor/parent/source/token and separate immutable image borrow remain alive throughout synchronous validation. The callback stores no borrowed SCM pointers beyond return, even on retained cleanup.

scm_descriptor validates actual owner/DACL and rejects null/missing ACLs or write/delete/ownership/configuration capabilities granted to principals other than actual operator, SYSTEM or built-in Administrators. It permits non-writing read ACEs and conservatively denies unsupported ACE kinds. Child descriptors are queried into the SAME existing check-descriptor slot, hashed, freed with checked LocalFree and rechecked before completion. Parent descriptor/current-token identity is also revalidated. This is an administrative ownership predicate; it neither applies ACLs nor proves service-token rights/CA isolation or minimum issuer ACL. Existing parent producer's requested native rights remain unchanged.

PS_LAB_BINDING is private C89 DATA: zero-initialized immutable facts bind target/config/image IDs, exact content and ACL hashes, actual operator fingerprint/token IDs and32-byte OS CSPRNG attempt. Config/image/operator/target mismatch, Stop, invalidation and replay reject; completion consumes READ-ONLY preparation only. No DATA result is wired to ps_binding_ready or an administrative grant. The printed nonsecret plan includes actual operator SID, target/config/image IDs, hashes, fixed service/account and attempt, with AUTHORIZATION=NOT_ACQUIRED and CREATE_SERVICE=DENY. The record is invalidated and backing closed/retained before exit. Logs cannot authorize a later invocation.

The existing console Stop handler is acquired by the SCM owner BEFORE image hashing and held until checked image/SCM closure, then unregistered through the existing function. The embedded four-byte flag fits measured native-owner alignment (12816 unchanged), not an assumed free resource; Windows registration/callback costs remain unknown. Synchronous I/O retains buffers until return, cooperative Stop invalidates the read-only receipt and no pending I/O is freed by timeout. The root does not install a second console handler.

## Shared runtime readiness and teardown

No new runtime/wait loop was introduced. ServiceMain marks its actual callback execution/thread, and the canonical C8 runtime calls the private readiness receipt only AFTER its existing owner/I/O/security preparation, immediately before the existing loop. Main still checks operational admission before listener acquisition; it remains DENY. Service mode avoids console-handler installation/reset, preserving the SCM Stop signal; direct mode retains its console path and requires no virtual identity.

RUNNING requires correct thread, active callback, one-shot pending lifetime, actual initialization producer call and no observed Stop. Controls are advertised only when RUNNING. Stop races recheck the signal. The canonical runtime reports STOP_PENDING before its existing teardown. Main emits the terminal receipt only after factual root shutdown, network try-shutdown, console cleanup and owned CLI-storage release. Retained root/failed cleanup records retained instead. ServiceMain cannot infer STOPPED from timeout or integer return: it checks the terminal receipt and lifetime before final report; otherwise retained containment. Model tests prove wrong-thread/no-callback denial, pending/ready/Stop/retained transitions, terminal non-overwrite and no premature STOPPED report.

These are producer hooks, NOT a positive service qualification. Current service host still has no operational configuration/admission handoff (argc1 fallback does not run the configured runtime); ps_binding_ready remains0. No native RUNNING/Stop cycle was attempted. TokenUser/groups/privileges of a real virtual-account service and private CA denial remain unqualified, as do productive ACLs and full ED11.
