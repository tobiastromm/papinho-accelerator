# Safe diagnostic identity, lifecycle and portability handoff

Status: implementation handoff; no new accepted ADR or permission to access keys.

## Exact identity contract

| Field | Source/validation | Missing or divergent |
|---|---|---|
| Provider | Fixed existing MS_KEY_STORAGE_PROVIDER, Microsoft Software Key Storage Provider | No alternate provider/fallback |
| Scope | Fixed MACHINE, existing NCryptOpenKey flags MACHINE+SILENT | USER not supported, no fallback |
| Purpose | DIAGNOSTIC_OBSERVE_EXISTING only | Create/sign/issue/publish unavailable |
| Authority and diagnostic generation | Explicit lowercase nonzero 32hex arguments, not RNG-generated by harness | Reject before native access |
| Full name | Explicit argument must equal PapinhoAccelerator.CA.<authority>.<generation> byte-exact | Reject before native access |
| Operator SID | Explicit argument, valid SID, compared by existing backend to effective thread/process TokenUser | Invalid/distinctness/token mismatch denies before provider open |
| Operational service SID | Explicit argument, valid and different from operator | Never inferred as LocalService automatically |
| Administrative appointment | Separate owner authorization of exact SID/purpose/name, not inferred from current user or membership | Future invocation remains unauthorized |
| Token | Existing effective thread-token query, process-token only when no thread token | No impersonation/elevation/token changes |
| Disposition | Existing owner, first-failure and close receipts; no retry after retention | Persisted key state remains UNKNOWN; no automatic delete |

No name or new authority is selected by this task. The historical potentially retained name is not reused, queried or reconciled. Merely passing a name on CLI is not administrative authorization. Future owner/executor review must bind exact arguments, selected executable hash and actual process/token to the isolated diagnostic object before any native query. No global key enumeration. No NTE_BAD_KEYSET => global absence inference.

The only accepted CLI shape is: readonly_diagnostic.exe --observe-existing AUTHORITY32 GENERATION32 FULL_NAME OPERATOR_SID SERVICE_SID. This is an interface description, not an authorized command. No real argument values are provided here. A new nonexistent name is not useful: this harness does not create keys. To diagnose creation later, the owner must resolve the conflict between native creation/property configuration and the present prohibition of DACL/export-policy writes. Never re-enable old --native-key or execute old artifacts as a shortcut.

## Reachability proof

1. Old fixture native branch removed from source, including private-export probe, RNG-selected key name, reopen and deletion. Every argument now returns2 before any key call; normal no-argument path runs six invalid-input checks only.
2. New harness has build-time #error unless PAPACC_CA_READ_ONLY_DIAGNOSTIC. Its only backend operation is open of exact identity plus normal close; no create API call from main.
3. The same macro must compile backend. In this variant create requests fail closed with NTE_NOT_SUPPORTED/LOCAL_GUARD/ENTRY before native calls. Entire create/set/finalize block and its SID-text/security-descriptor construction are excluded by preprocessing. Product without macro keeps original conditions/arguments/order. No dummy successful native function or permissive linkage stub.
4. Read-only executable imports only NCryptOpenStorageProvider, NCryptOpenKey, NCryptGetProperty, NCryptExportKey and NCryptFreeObject from NCrypt. No NCryptCreatePersistedKey, NCryptSetProperty, NCryptFinalizeKey, NCryptDeleteKey. NCryptExportKey's sole source call is existing validation with constant BCRYPT_RSAPUBLIC_BLOB; no private-blob selector/input or private export caller. Import absence alone does not distinguish public/private export; source call/type is essential.
5. Test executable replaces every reachable NCrypt function with doubles and imports none. Real read-only token/heap SD helpers do not apply DACLs to any object. The synthetic SD is a heap value only.

## Lifecycle and coverage

Backend guards/thread ownership/first receipt/checked close are unchanged in product. Read-only open success does not invent preparation, creation or finalization; diagnostic_finalization0 means NOT_OBSERVED. Closing key/provider handles is not key deletion and not PST DESTROYED. First receipt snapshot and current owner/close fields are logged separately without raw handles, key bytes or secrets. Retained handles/failed closes remain owned; no retry/reinitialization.

Local Ctrl-C/Break handler only marks cancellation atomically. Before open, cancellation returns without NCrypt access. After an already-running open/validation, existing close is checked once; cancellation never drops retained references. No bound is claimed for an in-flight Windows query; no product Stop thread or scheduling dependency is introduced. This standalone process is containment on exit, not evidence that retained resources or persisted key were destroyed. An offline callback during model_open requests cancellation; callbacks are test injection only, not new backend callbacks. Live signal and native close failures are NOT qualified.

Per Debug and Release:39 new assertions (identity missing/name mismatch/legacy switch, distinct SIDs, incorrect effective operator, create denied without native calls, pre-Stop and during-query Stop, close exactly once, first error immutable, close failure retention/no retry). Existing6 argument negatives and598 synthetic assertions/19 preimage comparisons pass. Detailed malformed SID/each individual Win32 failure and native token isolation are not exhaustively qualified. No new native key query, creation, export or deletion was performed.

## Portable issuer boundary review

Normative authorities: Accelerator ADR-0002 and PapinhoEngineering ADR-0007; accepted internal issuer decision clauses2,7,10 and technical profile sections2/3. Concrete CNG choice in3.1 is explicitly initial modern Accelerator backend, not a mandatory box/ISA mechanism.

| Domain contract, independent of platform | Existing authority | Current implementation/gap |
|---|---|---|
| Issuance and purpose-specific signing | Issuer clauses1,2,10; technical profile1 | Full portable issuer API not implemented; no signing entry point in private key component |
| Serial/identity/idempotency | Technical profile2.1–2.4 | Normatively fixed; same-root persistent reservation implementation pending |
| Revocation/status/renewal | Issuer clauses2,8 | Persistent history required; active Session policy pending |
| Persistence/publication | Issuer clause7; technical profile2.5 | Same root transactional authority, no shadow registry; full live issuer implementation pending |
| Custody/ownership | Issuer3–5; technical profile3 | Manual exception and automatic local key preserved; native types private to Windows adapter |
| Availability/capabilities | ADR-0002 derived9–10; Engineering ADR-0007 | Absent backend explicitly NOT_SUPPORTED; no CNG fallback or promised hardware support |

Search found no server_ca_key/NCrypt dependency in include/, src/security common contract or product CMake integration. Backend header remains apps/server/*_win32 private, not exported or required by common contracts. It is NOT a portable issuer header and must not be promoted wholesale into one. No Windows type leaked into common issuer API because that API does not yet exist. No unnecessary cross-platform API was invented to hide this gap. Box/ISA need a future capability-appropriate backend; no hardware implementation or qualification here.

Smoke compiles existing types/version/capability headers under real MSVC x64, with include trace containing no windows.h/ncrypt.h/bcrypt.h, and runs in both configurations. First experimental removal of _WIN32/_WIN64 broke MSVC CRT size_t; retained log, not a platform failure or justification to change CRT. Final smoke preserves real compiler target defines. This is header isolation, NOT a non-Windows/box/ISA build and NOT a full portable issuer implementation.
