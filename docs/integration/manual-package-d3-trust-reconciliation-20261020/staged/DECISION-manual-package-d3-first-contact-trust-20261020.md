## Acceptance findings

The first-contact trust assumption is explicit: the operator independently recognizes the administrator/role, and the approved channel conveys verified same-root purpose/status facts bound to this one immutable package. An in-person handover is the minimum ceremony; another channel needs an already approved applicable administrative authentication procedure. No channel qualification or new protocol is inferred. Package password, embedded SPKI/CA, mathematical RSA and a UI checkbox alone never establish trust.

Purpose evidence is attested by that independently authenticated administrator only after factual canonical root/policy/issuer and vetted certificate validation. The Browser must not claim local verification of an unseen signer certificate. Additional required independent certificate evidence is not waived. This delimited approved signer context follows the independent-confirmation option already allowed by M1; it does not replace certificate requirements or make arbitrary statements trustworthy.

Status is observed through actual applicable CURRENT for the same import, revalidated before release/installation, and denied whenever unavailable/expired/revoked/uncertain. Offline delivery has no global-current or revocation-freshness guarantee and no cached-evidence exception. Browser offline does not prohibit a trusted administrator obtaining source facts, but no source of proof means DENY. No TTL or recovery/fencing proof is invented.

M1 order is preserved, all confidential material remains quarantined until complete validation, and installation requires a separate authorized local BrowserProfile action. Same candidate/generation/store/lease ownership, Stop/retention, ED08/ED11, per-process limits and independent admission guards remain. There is no material normative conflict after this delimited reconciliation. Factual environment/provider/representation/lifetime/reservation gates remain open, not hidden as acceptance prerequisites already proved.
