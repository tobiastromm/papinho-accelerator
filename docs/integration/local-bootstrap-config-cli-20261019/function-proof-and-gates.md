# Prova focal e limites de integração

Slice A permanece bloqueado, sem criar contêiner: P3 exige criação e aquisição de custódia como uma operação protegida contra substituição de namespace. O caminho existente path_ok valida strings e atributos; o worker abre o alvo posteriormente por caminho absoluto. Não há lease dos ancestrais nem criação atômica de diretório com handle retornado no caminho atual. Adicionar CreateDirectory seguido de CreateFile introduziria janela de substituição; comparar file IDs depois não a fecha. Não implementar essa aproximação. Também faltam referências bootstrap factualmente autorizadas. A solução futura deve qualificar criação relativa a um parent sob custódia e demonstrar que o worker usa o mesmo objeto; não escolher primitivas como prova por mera disponibilidade.

Slice B é independente e antecipado no main API3, antes do dispatcher operacional, console, root, rede ou logger. A nova função despacha somente argv[1]=config. Todos os demais comandos seguem a CLI histórica. Opção OFF por padrão exige candidato API3; API2/prod064 não recebe fonte, link ou comando novo.

validate_source: frame exclusivamente local, leitura limitada a8193 bytes, fechamento único, parser/validator existentes, target um listener/Secure explícito. Campos e segredos não são impressos. SOURCE=VALIDATED é somente validação estrutural; qualquer bloco exige fonte root ausente e retorna2. Provider e SELECTED recebem diagnósticos específicos de pendência/negação. Nenhuma promoção MODEL_BOUND/RESOLVED. Sem referência externa (somente gates negativos), retorna0 com escopo offline explícito.

config diff: valida candidato mas, sem pin CURRENT, retorna indisponível2 e nunca produz diferenças. config show-effective: sem pin retorna indisponível2 e nenhum estado. config apply: retorna2 antes de abrir arquivo ou criar qualquer root/worker. Erros de sintaxe/IO retornam1. Comando desconhecido não inicia serviço. Não há sucesso fictício de comparação/aplicação.

Lifetime: documentos e input pertencem ao frame síncrono, sem callback, empréstimo, pin ou thread; nenhuma leitura dos objetos runtime. O main retorna antes de construir runtime em todos os comandos config. Root, slots, pins, Sessions, worker, I/R/A/P e retenção histórica não são alterados. Erro fclose é reportado, sem retry ou interpretação como commit/destruição. Não existe recurso root/lease/crédito adquirido nesse caminho. Stop/concorrência/retidos da root não são exercitados pela CLI sem root; regressões históricas serão relatadas separadamente.

ED11: não somar automaticamente workspace CLI ao cenário ALL2089223 como se fosse coexistência demonstrada. O hook no main prova exclusão funcional entre CLI e runtime dentro dessa invocação; símbolos estáticos runtime já existentes não desaparecem e seus custos não são reduzidos. Compilar sizeof do workspace, considerar frame/CRT/IO separadamente e manter custos transitivos/provider/kernel UNKNOWN. Nenhuma reserva operacional ou bootstrap é aprovada por esta mudança.

Revisão oficial solicitada apenas para quatro operações exatas em source-operations.json. Não aprova bootstrap, CURRENT, novo backend, carrier ou grants por referência.
