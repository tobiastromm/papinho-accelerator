## Exact format, ownership and limitations

Private Windows x64 little-endian frame1024: magic16, attempt32, DWORD version/kind/length/check16, payload960. Arm kind0 has zero payload. Final kind1 failure or kind2 prepare success has a bounded explicit length and zero remaining padding. Frame checksum is FNV-1a for accidental corruption/truncation detection ONLY; it is not authentication, authority or a substitute for protected native binding.

Operator prepares with CREATE_NEW, protected security supplied AT CREATION, no inherit-handle, exclusive share0 and OPEN_REPARSE_POINT. New file must have one link, no reparse/directory. One1024-byte arm write, flush and checked close. Existing object/collision is STOP; no OPEN_ALWAYS/CREATE_ALWAYS/TRUNCATE_EXISTING/overwrite/delete. Parent write permission is not granted to the service. The proposed creation-only DACL grants operator/SYSTEM/Administrators their approved administrative rights and the virtual service only file data read/write, attributes/read-control/synchronize (0x120083) on THIS new object. Exact owner/group/SD and native parent/file readback need official operation review; the fixture uses its own OW/admin/SYSTEM descriptor, not a claim about the VSA.

Service opens the already-created file OPEN_EXISTING with share0, compares factual supplied volume/index identity, link/type/attributes/size, arm attempt/format/checksum and exact1024-byte size. It performs ONE final1024-byte append from the pointer after exact arm read; original bytes remain unchanged. No seek-to-zero, truncation, retry, growth loop or append after a partial/uncertain attempt. Maximum own logical output2048. Service-native-ID delivery plus protected SD validation remains an UNIMPLEMENTED integration gate; a self-declared ID/header/path is not ownership proof. Capsule explicitly requires the caller's approved parent/SD/native binding.

Any acquired-handle failure marks retained and forbids close-as-cleanup through psrf_close; first error remains. Short write/flush/close failure is not confirmed rollback, deletion or durable final record. Parser validity alone does not replace flush/close/readback facts. The preparer/file persist as separate effects; no automatic deletion. Successful component receipt proves requested flush and handle close, not power-loss durability, physical sector persistence, canonical application retirement or original orphan cleanup. No arbitrary text/private key/payload dump is supplied by the actual trace fixture; no pointers/handles are serialized.

Stop before open performs no file acquisition. Stop after arm read and before final write retains the acquired handle and performs no append. Synchronous in-flight Win32 I/O has no fabricated cancellation guarantee; timeout is not quiescence. No additional worker/thread is introduced to force cancellation. Failure paths preserve a resource owner; future runtime integration must register that state in the SAME existing native owner and retirement guards before it can be used.
