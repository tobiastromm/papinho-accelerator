# Provider/kernel source recipe: observations, identity and unresolved envelope

This recipe is a collection/interpretation specification, not a numerical policy or admission grant. No provider/kernel ceiling is asserted. It uses existing owners and collectors; no new recorder, authority, daemon or public wire field. Sources inspected: apps/server/server_c8_target_evidence_win32.c; src/network_egress/c3_bridge_win32.c; server_c8_target_evidence_win32.h; previous e19-e20 topology/inventory and actual extracted consumer evidence. Claims below derive from those sources, not recollection of undocumented Windows behavior.

## Artifact scope

Archive separately exact Browser VC6/x86 NSS/NSPR package and mapped module identities and Accelerator Selected/Legacy OpenSSL/x64 build/library/provider identities. SDK/public version equality is not mapped image byte authentication. Bind process PID/creation, owner thread, local clock domain, root/revision/policy/epoch, operation/generation, profile and origin. Distinguish native origin2 from synthetic origin1. An absent field is absent, never zero-as-absence. Each owner retains its local original sample, validation time and expiry; exporting does not renew them and participant clocks are not compared.

## Collection phases and categories

At baseline/prepared, pre-admission, setup, active bridge/TLS, orderly shutdown, release, final and retained outcome collect original owner series and acquire/release ledger. Current C8 collector uses GlobalMemoryStatusEx, GetProcessMemoryInfo, GetProcessHandleCount, GetProcessTimes and pst_get_version, with five individual API errors retained. It measures local collection duration and finite-series continuity; native observations are distinct from quantitative authority.

- Host available physical and commit: bytes; one host observation, not additive per participant. Not a per-connection promise or reserve.
- Process PrivateUsage and working set: bytes; whole-process scopes, not disjoint provider/queue/stack compartments. Track sampled peaks separately from unknown unsampled maximum.
- Process paged/nonpaged pool quota observations: bytes; existing source explicitly does not bound provider/kernel per Connection. Do not add these again to a process total or call them a complete TCP allocation recipe.
- Native handles: count in one process table; owned duplicates are distinct references, borrowed handles are not extra owned references. Persistent files after close are not live handles. Handle values have identity/lifetime scope, not global cross-process uniqueness.
- Controlled C2/C3 storage: exact compiled object/buffer bytes and explicit live/retained multiplicity; shared durable root, credential/trust, scheduler/managers charged once to original owner. These allocations overlap process totals and are not added as another total-memory charge.
- C3 setup_listener/setup_connector/peer and external-source/PST/transport references: acquisition, registration, transfer, last use, close/release attempt/result and retained disposition. Existing close_owned_once/close_attempted prevents automatic retry; retained-terminal keeps dependencies. Socket SO_RCVBUF/SO_SNDBUF calls in C3 are requests, not a demonstrated complete provider/kernel ceiling.
- Provider allocations: identify actual public allocator/envelope/counter source if supplied by the exact backend SDK. Missing counters/envelope stay UNKNOWN. NSS/NSPR and OpenSSL measurements are independent; one architecture's recipe cannot certify the other.
- Thread/stack/PSS/observer: own/borrowed/transient references and measured stack committed/reserved VA are distinct. Collector overhead stays separately attributed to its actual process; no full transient maximum inferred from sampled windows.

## Recipe validation before any positive policy

A recipe must name sources, versions, object scopes/units, native-versus-synthetic origin, knownness/errors, temporal interval, process creation identity, owner generation, multiplicities and overlaps. Missing API/error status, module/backend mismatch, absent required identity/arithmetic overflow/clock regression/ambiguous domain, replaced identity, Stop/revocation, history loss, dead owner or unclosed retained reference invalidates positive applicability. Equal hash alone does not repair missing native/process identity. Controlled release proof cannot be replaced by process-private reduction.

The present source-level observations can populate measured categories, NOT provider/kernel known flags or a universal hard cap. A complete future admission recipe requires either supported verified hard bounds for all mandatory categories or an explicitly approved narrowly scoped empirical residual treatment. Until then RESOURCE_UNKNOWN/DENY is correct. Product freshness/headroom policy remains separate from C8 diagnostic1000ms/cadence100ms and LAB60s/1s,5/9GiB.

A metric whose API/presence/classification is complete may factually be zero; zero must not stand for absence. See ../PROVIDER-RECIPE-PRIMARY-SOURCE-CHECK.md for official API interpretation and explicit inference limits.
