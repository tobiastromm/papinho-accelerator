# Native proof source review and literature boundary

The selected protocol is a salted unbound HMAC session with encrypted GetRandom response, not an audit session. The initial audit alternative was rejected for this minimal profile to avoid changing audit-session exclusivity. No audit-setting command is present. StartAuthSession uses existing qualified private-capable EK only; no AK/CreatePrimary/hierarchy secret is needed by this profile. Absent compatible accessible EK => DENY, no fallback.

Primary references reviewed:
- https://raw.githubusercontent.com/microsoft/ms-tpm-20-ref/main/TPMCmd/tpm/src/command/Session/StartAuthSession.c : salting requires private decrypt material; this operation does not authorize use through the object's hierarchy auth.
- https://raw.githubusercontent.com/microsoft/ms-tpm-20-ref/main/TPMCmd/tpm/src/subsystem/Session.c : session key derived from salt and both nonces under ATH; NULL bind contributes no entity authorization. This is not a guessed empty owner password.
- https://raw.githubusercontent.com/microsoft/ms-tpm-20-ref/main/TPMCmd/tpm/src/main/SessionProcess.c : extra encryption session, response parameter encryption precedes rpHash, HMAC authenticates new nonce/attributes, continue-clear removes session under TPM semantics.
- https://raw.githubusercontent.com/microsoft/ms-tpm-20-ref/main/TPMCmd/tpm/include/private/CommandAttributeData.h : GetRandom response supports parameter encryption; this profile does not request an audit session.

The proposal verifies knowledge of the pinned EK's private decryption material at the TBS-accessible endpoint. It is not attestation of physical locality, uncompromised Windows/TPM, non-revocation or original NV generation. An OS/TPM proxy or compromised device is outside this mathematical conclusion. Software tests don't establish native interoperability. Native proof mode and all TPM APIs were NOT executed. No valid owner approval file exists in this package.
