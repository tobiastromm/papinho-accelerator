# Isolated durable worker — integration and proof boundary

Implementation: durable_worker_fixture.py. This is executable nonoperational worker integration of the candidate record codec, one exclusive fixture owner, append/flush/readback storage, a separately retained simulated witness, immutable approval/context bindings and one-use sequencing. It does not introduce a product persistence authority. All actual paths are restricted to this package's runs subtree; files have synthetic marker names and records, not live root/CURRENT/intent files. No TPM sender exists in this worker.

The canonical root DATA API, owner, CAS and ROOT8 formats are unchanged. L1 still requires exact participant/schema/native-preimage review before applying a durable extension in product. The physical fixture format is an explicitly unapproved experiment, not a hidden update of ROOT8 or issuer events. No service, registry, IPC, daemon or operational journal is introduced.

Storage: one synthetic root file, initial R byte, append-only Q4CF frames: magic4,size4,previous-frame digest32, candidate record372. One frame412 bytes. Normal PREPARED/CONSUMED/RESULT file1237 bytes including initial byte. Hash checks detect corruption/chain forks but do not authenticate adversarial storage. Same fixture owner holds a nonblocking Windows byte-range lock for its lifetime; independent process contenders deny BUSY or replay. File device/inode identity is checked against the path; this is controlled fixture identity evidence, NOT RAW1/native protected ancestry or canonical root original-handle proof. All production participants would need the actual existing owner's native/CAS guards, not Python advisory locks.

Every append performs fsync and exact readback before the simulated witness may increment. Counter file has device-generation digest32,value8,checksum32; this second file is deliberately simulated and not designated as independent persistence. Increment and local commit have a crash gap; restart denies any PREPARED/CONSUMED/RESULT/UNKNOWN rather than adopting it. Runtime Stop or ambiguous increment records UNKNOWN when the intact chain permits, preserves the first error and never resends. A failed/torn store is not retried/repaired. Missing witness denies before acquiring a model read slot. No actual protected reader is implemented.

RESULT is now written by the isolated worker, unlike the earlier state-only model. Local-only restore is rejected against the retained simulated counter. Restoring BOTH files reproduces old state and can pass: this explicit negative guarantee test prevents describing a second local file as hardware anti-rollback. No actual NV persist/reboot or power-loss guarantee follows from fsync/process termination tests. Reboot tests mean a fresh Python process, not rebooting Windows/TPM.

Close UNKNOWN is simulated: receipt retains UNKNOWN and forbids reuse, but test process termination subsequently releases its synthetic OS references. This is not evidence that a live operational owner retains uncertain handles/dependencies correctly. The result file is preserved; the separate captured fixture receipt records close uncertainty. Real Model E handle retention and complete native RAW1/CAS lifecycle remain product-integration obligations.

After a forced exit before any PREPARED byte is persisted, an empty synthetic root and unchanged counter can accept a new synthetic call. This test is not permission to retry a consumed owner approval. The fixture is not an approval authority; real one-shot execution records and the exact original live invocation remain mandatory. Known missing state may never bootstrap as virgin in production.

Memory/stack/provider/kernel cost is not zero and not measured as an admission envelope.1237 serialized bytes is not RAM cost or an ED11 credit. Native resources, plaintext credential custody and hardware availability are not inferred from fixture success.
