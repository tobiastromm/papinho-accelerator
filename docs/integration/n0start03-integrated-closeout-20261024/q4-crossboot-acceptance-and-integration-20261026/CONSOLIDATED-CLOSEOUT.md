## Source audit and technical result
The canonical launcher checks exact approval hashes but that does not itself durably consume documentary authorization. lab_intent in scm-registration-lab.c and scm-runtime-cycle-lab.inc creates and flushes narrowly scoped historical operational intents; psr-file-capture-lab.inc and existing placement helpers implement exclusive protected creation and flushing. None of these reviewed mechanisms establishes an independently designated documentary ledger, append-only external anchor or rollback-detection authority for this readback. Reusing their old intents would violate scope. A durable claim protocol cannot be declared integrated merely by copying those APIs.

Prior isolated C# Debug/Release builds, zero warnings, sixteen filesystem/restart/concurrency scenarios and seven model regressions are reused unchanged. No campaign repeated. New discriminating experiment executes the existing Release fixture in two preserved synthetic namespaces representing original state and a restored pre-claim state: both accept the same synthetic authorization text. This demonstrates the limitation of marker-only absence checks under the modeled rollback. It is not an actual storage restore or a protected-object test. No files deleted or overwritten.

Original-handle protection prevents substitution while references live; it does not provide a persistent witness of an erased pre-reboot claim. Hashes, file names, exclusive creation and FlushFileBuffers alone cannot establish that absent consumption never occurred. A current boot also cannot reconstruct old lifetime/identity facts. Supplying a fallback that assumes otherwise would weaken the accepted rule.

## First unresolved prerequisite and concrete alternatives
STOP before canonical integration: no suitable existing governed approval-consumption ledger is designated or demonstrated in the reviewed mechanism. Consequently no cross-boot production reader, operational claim, new registry or executable approval request is installed. Technical changes cannot fill this authority gap by inference.

A. Designate an actual existing governed non-rollback consumption authority, its original native identity/protection, threat model and durable exactly-once protocol. Qualify partial writes, flush/close UNKNOWN, concurrency and restart/rollback reconciliation before integrating its adapter. No such identity is fabricated here.

B. If none exists, explicitly revise the accepted cross-boot contract to approve a narrowly scoped documentary consumption journal and bounded storage-failure model. That is a new normative choice, not covered by acceptance of the original bytes. Specify independent witness/reconciliation after ambiguous absence, no retry, and whether privileged rollback remains outside the guarantee. A local file cannot promise unrestricted rollback resistance.

Keeping the current accepted contract without either condition leaves readback DENY. There is no safe code-only replacement for the missing durable authority. This is the approved ADR's explicit STOP, not a request for per-edit authorization.
