# Proposed custody and actual proof boundary

Use the existing canonical root participant and explicit operator context for any future Q4 credential custody, never a second generic vault. A possible protected payload uses Windows DPAPI CurrentUser, binding entropy to actual root/device generation/index/public profile/approved purpose. Test code uses a fixed public synthetic vector and no real credential. It writes only DPAPI ciphertext at exclusive new package paths. Ten separate outside-sandbox processes demonstrate same-user recovery and rejection of wrong binding/corruption. Initial sandbox encryption failure is retained, not reclassified success. Cross-user/native-token/RAW1 and power-loss semantics are not proved by this test. Managed arrays are cleared best effort; provider/GC/OS copies are not guaranteed physically erased.

DPAPI protection is NOT a rollback witness, not an authentication of hardware, and not secrecy from other software acting as the same operator. Machine/profile loss, password reset/reinstall and unavailable master protection can make a blob unusable; that strands the credential/index and denies use, never permits automatic recreation or adoption. Owner must actually designate the allowed account/custodian and protection/lifetime before operation. No actual secret is generated or stored by this task; test plaintext is a public deterministic vector, output only ciphertext and status. Software KSP CA key stays purpose-separated, not used to encrypt arbitrary passwords or copied as a store.

Actual hierarchy authorization is unavailable as evidence. Admin token and TBS availability do not imply possession. No ownerAuth API/registry extraction, guessed/empty password or wrong real auth attempted. Candidate per-index credential remains32randombytes generated only in a separately approved provisioning ceremony, not a new example password. AUTHREAD/AUTHWRITE with NO_DA clear requires no wrong-password retries because lockout is a real consequence. Preserve nonexportable/auth session boundaries and all original dependencies on uncertainty.

The isolated write work implements standard SHA256/HMAC transcript construction and verification for a one-shot NV_Increment session and encrypted DefineSpace packet preparation, using only synthetic session handles/nonces/key material and mocked endpoints. Windows CNG AES128-CFB128/KDFa context preparation is tested with public vectors. It is not a complete TPM library, salted-session key exchange, hardware authentication or live HMAC channel. No self-written cipher/provider is introduced. Missing live session/provenance/parameter-encryption binding must be qualified before any live write runner is connected. The original read-only NativeTransport exact allowlist rejects these increment bytes.

Root schema boundary: W/L designates the existing owner and ledger architecture but does not change ROOT8/issuer fixed bytes. New helper copies logical root/pin fields only under existing lock/thread/current/ticket/Stop guards. It does not persist use, release credits or grant authority. A new documentary durable component needs its exact versioned schema and worker review under L1; no issuer serial/event, epoch or reserved field was repurposed to make it appear integrated. No claim of a deployed complete durable ledger is made.
