## Maximum coexistence is NOT bounded by these numbers

Required graph may include old qualifier, old launcher and unresolved old-host obligation, plus future qualifier/launcher/host and a diagnostic receiver. This is a role inventory, not a proved maximum process count. Transient CLR/compiler/service/OS participants and shared allocations are not bounded by counting those roles. No new receiver/driver operation is qualified here.

For each relevant resource domain d, admission requires a justified retained old bound R_old(d), new peak N_new(d), shared-attribution cost S(d) without unsupported deduplication, and factual host margin/capacity H(d), in addition to each applicable process/quota constraint. None can be replaced by PE file size or nominal headroom.

The first missing numeric term is the old qualifier/launcher aggregate native user/kernel retained upper bound. Later independent missing terms include new total peak, transitive stack/SCM/provider/kernel/receiver costs and host available capacity. Known fixed statics do not bound any of these opaque costs. No maximum coexistence value can be honestly supplied. O0–O5 does not demand cleanup as the only theoretical route, but it also grants no zero/refund for unavailable evidence.
