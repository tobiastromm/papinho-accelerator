# PT0-PT7:conditional protocol-source profile

This focal proposal accompanies AT0-AT9 Revision3. No field/API/wire/algorithm/layout is accepted or implemented. R1 is RFC 10049, pinned by rfc10049-reference.json in this review; the exact profile clauses below govern this proposed revision. Prioritize its study as the owner-preferred B candidate,not operational selection. No vendor,key or endpoint is assigned.

## PT0 Exact reference, acquisition and byte limits

Proposed profile RT1-UDP-2048 uses only RFC 10049 as published October 2026, Roughtime version 1. Its official text is pinned by rfc10049-reference.json. Incorporate the RFC's complete encoding, signature, delegation, request correlation, validation, grease and security rules by reference; no project wire fields, custom errors or experimental versions. Only version 1 is advertised/accepted. Unknown tags are handled by the RFC, not treated as extensions with authority. A normative erratum/update changing interpretation requires explicit profile revision before implementation; do not silently apply or ignore it. Errata disposition must be verified at the acceptance review.

Configure exactly three sources operated by three distinct administrative parties. No vendor is selected. Source independence and at least one correct, calibrated source throughout the campaign must be independently qualified; signatures do not prove this premise. Perform exactly six sequential successful exchanges, source order A,B,C,A,B,C. Select the initial order using qualified entropy; chain fresh nonces exactly under RFC 10049 section 8.2. All six replies and causal-order checks are mandatory. Do not substitute another source or retry a failed exchange in this campaign. At most one campaign, one outstanding request and one transport operation exist per process, including retained/uncertain work. An occupied retention slot blocks a new campaign.

Local admission limits, counted in octets including the RFC outer header: every outgoing request is exactly 2048 bytes; every incoming response is at most 2048 bytes and at most its corresponding request size. Use the RFC padding tag to reach the exact request size; no private framing/padding. This cap accepts only the representable subset of valid RFC replies; an oversized valid reply is unsupported locally, never truncated and parsed as complete. UDP path delivery/fragmentation is not assumed. Failure on the deployed path denies; TCP fallback is not enabled in this profile.

Parser limits per datagram: four parsed maps (outer response, SREP, CERT, DELE), maximum map nesting depth three counting outer as one; at most 32 entries per map, 128 total entries; unknown values remain opaque bounded slices, never recursively parsed. Requests contain the RFC mandatory fields plus SRV and padding; responses require all RFC mandatory fields and exact fixed-field sizes. Enforce RFC offsets, alignment, sorted/unique tags, bounds and complete consumption before semantics; no trailing datagram bytes outside the declared packet, overlap, truncation or arithmetic wrap. Reject unsupported maps/limits rather than reinterpreting them. PATH is at most 32 hash nodes (1024 bytes), further constrained by the packet cap; version lists are bounded by the RFC and only the selected version is usable. No additional wire structures are defined.

Reserve six immutable request slots and six immutable response slots of 2048 bytes each (24576 bytes). Also reserve six 32-byte nonce-chain random values (192 bytes), parser scratch 4096 bytes, hash/Ed25519 scratch budget 16384 bytes, six metadata slots of 256 bytes (1536 bytes), three source/evidence descriptor slots of 512 bytes (1536 bytes), and campaign/control storage 4096 bytes. These are proposed implementation ceilings, not measured sizes or authority-bearing record layouts. Descriptor limits include owned identity bytes but exclude external credential/status graphs, which must be separately charged. Complete C89/backend/stack feasibility must be proved; if any ceiling is insufficient, stop rather than allocate outside the census. See ed11-census.json.

## PT3 Exact conditional Q1 construction and uncertainty policy

Validate the entire six-exchange campaign, canonical trust/status and RFC causal ordering before constructing any positive observation. Reject detected divergence for the entire operation; retain evidence, invalidate applicability and require explicit source requalification/new governed operation. Do not average, select a favorable server/interval, retry until favorable, or treat apparent majority as clock correctness. No reporting endpoint or automatic source-list updater is authorized by this profile; keep local evidence for the existing administrative review. RFC reporting requirements must be assessed explicitly if such an endpoint is separately configured.

For each reply i, record m0_i before request generation and m1 after final campaign verification. Independently qualified source evidence must bound actual UTC at a proved processing/reading instant g_i between these cuts. Authenticate protocol bounds; source calibration/health must justify them. RADI is not PAL E. Convert native seconds to Q nanoseconds with checked unsigned arithmetic. Outward-enclose the RFC open interval by the closed [Ls_i,Us_i]=[(MIDP_i-RADI_i)*1000000000,(MIDP_i+RADI_i)*1000000000]. Reject negative lower endpoints, overflow, missing calibration, unknown leap/scale interpretation or bounds narrower than qualified source error. No smear assumption or double-counting: any extra source quantization/calibration uncertainty must already be included conservatively or cause rejection; never narrow authenticated bounds.

Let d_i=m1-m0_i. Under qualified Q2 rho/E covering every cut, du_i=ceil(d_i*(rho_den+rho_num)/rho_den)+E. Form [Li,Ui]=[Ls_i,Us_i+du_i]. Use the hull of all six intervals: L=min(Li), U=max(Ui), not their intersection. This preserves inclusion if the qualified source model supplies at least one correct reply; inconsistent causal evidence still denies. All sums/products/conversions checked, no saturation. This is a conditional inclusion proof, not qualification of any deployed server or PAL.

Reject U-L greater than 30000000000 ns (30 seconds) at m1 and again at the effect after Q3 propagation. This is a rejection ceiling, not granted accuracy, clock skew or extra certificate validity. Maximum local observation age at effect is strictly less than 1000000000 PAL ns (one second), in the same operation only. Also require effect before the campaign's total deadline and before every factual source/status/PAL applicability boundary. D is the minimum of those qualified monotonic boundaries and these two local caps; caps only shorten independently proved applicability and cannot create it. A civil expiry cannot be directly compared to monotonic D: revalidate through the full propagated interval under Q3. Unknown mapping or nonrepresentable exclusive deadline denies.

Use the accepted Q2 direction and Q3 propagation unchanged, including E at d=0 and independent resolution/read/conversion errors. rho and E have no numeric defaults. No qualified PAL continuity means NOT_QUALIFIED even if all signatures pass. Rollback, unknown health, source/root/configuration change, suspension without continuity proof and restart invalidate; no query extends D. All issuer/certificate/delegation civil validity checks retain full interval inclusion in their accepted domains, separately from RFC delegation semantics.

## PT7 UDP transport, deadlines, failure and qualification gates

Use only RFC 10049 UDP framing, one complete packet per datagram, no PST/PACC/Site TLS/operational listener. Send from the existing administrative backend as an outbound client, not an Accelerator service. Each authorized source has one administratively approved numeric unicast IP address (IPv4 or IPv6) and UDP port 5319. No hostname discovery, public-list enrollment, multicast, broadcast, redirect or runtime address fallback. No actual address is selected by this proposal. Endpoint matching filters unsolicited traffic; authentication is pinned-key RFC verification plus canonical source status, not IP identity. UDP gives no confidentiality; send only protocol-required public material and fresh qualified randomness, never issuer keys or client secrets.

All deadlines use checked PAL monotonic nanoseconds and apply to the complete native operation including uncertainty/retention. From campaign start t0: total deadline t0+60000000000 (60 seconds). For each exchange beginning at si: send must factually complete before si+1000000000 (one second); one matching reply must factually arrive before si+4000000000 (four seconds), and no later than 3000000000 (three seconds) after send completion. Final verification of that exchange must finish before si+6000000000 (six seconds). Every cut must precede the total deadline. Equality with any deadline is expired. Overflow, failed/unknown PAL or continuity invalidates. These are rejection limits, not timing/CPU guarantees. Existing scheduling must enforce checks without a new worker.

There is no retransmission within the campaign: six sends maximum; loss, malformed/unexpected packet, invalid signature, wrong source/nonce/type/version, oversize datagram, failure or expired cut terminates the campaign with no observation. Detect truncation at the datagram API and reject the entire packet. After accepting an exchange, any duplicate/late reply is never reassigned to the next request. A datagram received while awaiting another exchange that cannot be matched fails closed; a stale datagram cannot advance state. Socket receive buffering is bounded by the native adapter's separately measured resource budget. No unbounded drain loop. Correlation uses the entire retained RFC request/proof, not nonce equality alone.

Across failed campaigns enforce exponential send backoff: initial one second, double per consecutive transport/protocol failure up to 86400 seconds, calculated without overflow. Reset this retry interval only after a properly signed response, as required by the RFC; independent administrative denial/health/quarantine is never cleared by that reset. In addition, campaigns start at most once per 60 monotonic seconds per process, whether successful or failed. No automatic retry after source divergence, compromised/unknown trust or quality failure; explicit requalification/new authorized operation is required. Restart cannot bypass guards by restoring authority: no campaign until administrative/entropy/PAL requalification; impose the maximum 86400-second local backoff unless an independently protected existing mechanism proves the applicable prior backoff. No new persistent journal is authorized.

Stop forbids sends/new observations/effects immediately, requests supported native cancellation without waiting, and marks all results unusable. Timeout, cancel request or error does not prove completion or free memory. Keep one campaign graph and credits retained until every I/O/crypto callback/borrow is factually quiescent and native close is confirmed. A result of unknown completion remains RETAINED/DENY and blocks replacement; no retry, socket/buffer reuse or cleanup by timeout. After factual closure, release/zero operation buffers under existing ownership/exactly-once rules. Audit evidence retention beyond that point must use an existing approved bounded mechanism, not an added archive.

The exact proposed transport/limits/trust policy is now defined above; operational gates remain distinct: accepted canonical source-key/status representation if required, actual authorized sources and independence/calibration, qualified entropy and PAL rho/E/continuity, primitive/backend C89 feasibility, all external lifetime protection, factual CURRENT, and complete measured ED11. Missing facts yield NOT_QUALIFIED/NOT_SUPPORTED, not permissive defaults. No positive issuer/UPDATE/CURRENT/signature/recovery/TRUST/admission authority follows. No implementation is authorized by this proposal.
