## Official Microsoft evidence (consulted 2026-10-22)

- [CreateServiceW](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-createservicew): explicit virtual logon name, NULL password, Windows7/Server2008R2 floor. NULL logon would select LocalSystem and must not be used. Requesting SCM creation rights does not confer CA authority. Existing service/collision errors are not permission to overwrite/adopt. The account/password selection is API-supported, not a positive installation test.
- [Service Accounts Step-by-Step Guide](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-server-2008-R2-and-2008/dd548356(v=ws.10)): virtual accounts require no administrator password management; no separate SAM provisioning. Domain network access can use computer identity; virtual account does not itself forbid egress. No domain infrastructure is required by the chosen local profile.
- [SERVICE_SID_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/ns-winsvc-service_sid_info): UNRESTRICTED adds a service SID to the token with documented attributes; RESTRICTED has additional restricted-token semantics. Neither value is the logon-account selector or an ACL grant. Name/SID resolution is distinct from actual token verification. Documentation notes system restart for configuration effect; do not infer that write/readback has changed an already live token or silently restart the host. Initial stopped creation and subsequent real-token observation must be qualified; if a target needs reboot, report pending and require separate action.
- [ChangeServiceConfig2W](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-changeserviceconfig2w): SERVICE_CONFIG_SERVICE_SID_INFO uses SERVICE_SID_INFO and requires SERVICE_CHANGE_CONFIG; check errors.
- [QueryServiceConfigW](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-queryserviceconfigw) and [QueryServiceConfig2W](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-queryserviceconfig2w): read account/binary configuration and optional SID type with SERVICE_QUERY_CONFIG. Bound buffer acquisition and returned pointer/string ranges; reject overflow/truncation. Configuration readback is not proof of the current running token, and pending configuration can differ from it.
- [Service security/access rights](https://learn.microsoft.com/en-us/windows/win32/services/service-security-and-access-rights): request operation-specific rights; separate service-object DACL from filesystem/KSP ACLs. Do not grant broad configuration rights to the operational principal.

These sources establish implementability, not target qualification. They do not prove current ACLs, actual runtime TokenUser, private-key denial, provider/kernel bound or Windows7 execution.
