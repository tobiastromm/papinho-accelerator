## X509 implementation

server_issuer_x509_win32.h/.c builds unsigned TBSCertificate and verifies complete DER using reviewed Crypt32 encoders/decoders/hash/signature routines. CSR verification is the preceding public validator: exact CSR/full-DER-SPKI SHA256 digests, RSA2048/e65537, SHA256RSA, canonical DER and proof of possession; unsupported attributes remain rejected. The constructor is public-data preparation, not authority: only the signer path requires the validated CSR and actual authorized root record before effects.

Client CN is exactly Papinho Client +lowercase32hex device-record ID; package CN is Papinho Package +ID. The CSR name is not imported as identity. Leaf version3, canonical positive serial from reserved8-byte prefix+unsigned64 counter (including the required sign-padding edge00/80), explicit exact validity<=90days and within CA interval, BasicConstraints critical CAfalse, KeyUsage critical digitalSignature only, exactly one noncritical clientAuth/codeSigning EKU, AKI and SKI are emitted. No client SAN, keyEncipherment, mixed EKU or implicit server profile exists. The verifier reconstructs the expected TBS from the record/public key and compares exact bytes, checks outer algorithm/canonical encoding and actual public signature under the supplied CA key. It rejects extra/unexpected extension content, names, validity, serial, algorithm or key digest. This intentionally validates certificates produced by this exact private issuance profile, not every semantically equivalent external certificate encoding.

The supplied immutable public CA must match root authority/generation prefix, CA v3/self-issuer name and serial1, canonical Papinho CA authority CN, full-SPKI digest, RSA2048/e65537/SHA256RSA, exact1825day interval, BasicConstraints critical CAtrue/pathLen0, keyCertSign+cRLSign critical KU, no EKU and the minimal three-extension supported public CA model. A different CA extension model is UNSUPPORTED, not silently normalized. Root CA self-certificate creation/selection/chain validation remains an upstream qualified public-material requirement; a decoded CERT_INFO alone does not prove its source or self-signature. There is no CA initialization in this component.

Key identifiers use the vetted CryptHashPublicKeyInfo SHA256 routine and32-byte OCTET STRINGs for initial public preparation, avoiding SHA1 even for identifiers. AKI copies the selected CA SKI; historical CA/certificate bytes are never modified or migrated. No own cryptographic primitive or signature downgrade exists. Exact NT4/Browser interoperability of the generated profile/32byte identifiers remains NOT_QUALIFIED. Package codeSigning certificate alone does not delegate package authority: the administrative callback must prove the separate purpose mapping. No arbitrary package payload can be signed by the CA through this interface.

## Native CNG boundary and lifetime

The caller supplies an already-open existing PAPACC_CA_KEY. The adapter never calls create/open/delete/property-write APIs, changes ACLs, chooses a different KSP, exports private material or elevates. Existing validation checks operator/service SID separation, key properties/export-policy0/sign-only usage, RSA2048 public blob and DACL. Accepted authority/generation-derived key name and publicly exported SPKI must match the selected root CA. Public export uses CryptExportPublicKeyInfoEx for RSA public info only.

The existing key owner now has ONE borrower pointer (+8 bytes, total480), not a second registry/pin authority. Borrow/return require that owner thread, READY state, exact holder and no close attempt. close rejects while borrowed before marking attempted or calling native frees. Acquire installs the factual borrow and captures the exact key handle; final checks ensure holder/handle still match. Other code cannot legitimately rotate/close the key through its owner while that lease is live. Private caller storage and all CA/public/root backing remain alive through any retained operation.

The signer revalidates root identity, policy, native key, UTC validity and Stop immediately before one NCryptSignHash with SHA256/PKCS1-v1_5, NCRYPT_SILENT_FLAG and fixed RSA2048 signature capacity256. Exact DER output size is queried PUBLICLY before the private effect; there is no private size-query signature. Raw CNG status is preserved with stage4 (NCryptSignHash); forwarded validation/borrow/return stages are separately identified, with existing key first-failure receipt retaining native/local details. Public API Win32 errors are not fabricated from structural failures or stale GetLastError.

A completed private result sets a completed lease state, so the lease cannot sign twice. Any native failure, unknown length, Stop after private effect or encoding failure retains the lease/workspace/key borrow and caller output through the core's existing uncertainty path. NTE_PERM is not permission to switch provider/keys or retry. Return failure preserves native error, holder and core lease. On known success, release removes only the completed borrow; actual key ownership/close remains with the existing key owner. No operation uses timeout/process exit/FINAL as destruction. Core serial/high-water/idempotence/revoke/renew/recovery logic is unchanged, and root CAS failure cannot fall back to historical authority.

Stop is serialized on the core owner; the adapter observes the same core Stop plus its local Stop guard. New code has no thread, lock, waiter, supervisor or scheduler. Native calls are synchronous and may block. Tests prove logical checks before/after effects, NOT cancellation or bounded latency of a hung real CNG/provider call. Do not attach this component to active operational scheduling or claim Stop responsiveness until native administrative execution/latency and existing lifecycle composition are qualified. Operational root Stop is unchanged because the backend is not installed there.
