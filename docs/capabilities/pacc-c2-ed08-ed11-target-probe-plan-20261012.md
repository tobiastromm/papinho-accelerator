## User memory measurements
- Managed requested/actual allocations have owner IDs, size/alignment, references and peak. Compiler sizeof/layout listing accounts metadata/wrapper/callback/timer structures; retained allocations remain live.
- Process private commitment and physical working set are reported separately; include committed/reserved stack, loaded module shared/private maps and heap allocator slack. Working set is not private commitment; do not sum overlapping metrics.
- Normal PST/provider incremental peak uses same-host staged deltas with known other workloads held at barriers. Differential measurement can establish an empirical envelope, not a hard input-independent maximum or precise provider allocation attribution.
- Record copied DER/trust/config/ALPN/peer-info buffers and size bounds. Peer network certificate complexity/length must be constrained by supported public contract; fixture sizes alone cannot prove hostile-input maximum.
- All spans borrowed from an already-charged queue are annotated, not double-counted as new memory. Test trace/artifact buffers are separate diagnostic overhead, excluded only with an explicit normal-versus-test ledger.

## Kernel and external measurements
Count actual sockets/events/windows/timers/handles and their lifetimes, including setup listener and retained objects. Record requested AND observed socket option sizes. Requested16KiB buffers are hints/controlled requested values, not certified total TCP allocation.

Use target-supported OS counters/instrumentation where available, retaining per-process versus system-wide distinction. On NT4, system pool deltas/background workloads may be the only available evidence; state attribution uncertainty, never label it exact per-socket memory. Unobservable kernel/provider budget remains unknown; no0 filling. External Site resource/receipt is fixture evidence, not local resource quota or general send guarantee.

## Queue sweep and candidate envelopes
Run8/16/32/64KiB queues in explicit test configurations with all other fixture/package/target settings equal; do not silently overwrite approved64KiB lab configuration. Observe peak, liveness, partial output, control/ACK scheduling and loss cases. Compare candidate managed caps512KiB/op,16KiB/Session, Browser2MiB and Accelerator2MiB controlled processes, plus proposed full user/kernel envelopes20/2MiB Browser and32/8MiB Accelerator.

Proposed2MiB opaque context thresholds and runtime shared8/4MiB are hypotheses only. A single pass or average is not a hard bound. If actual peak exceeds any candidate, fail that candidate, preserve evidence and return revised recommendation; do not enlarge silently or discard warnings. Actual NT4 machine headroom decides compatibility, not a guessed RAM figure.

## Oracle and completion
For every phase retain inputs, aligned sizes, U/K/X category, allocation identity/generation, actual peak/current, fixed quota reservation/retention/free and first divergence. Exactly-once native identity proof belongs in its own trace; total memory deltas do not prove no double close.

PASS requires pre-accepted cap policy, every required category accounted/bounded, correct old-target headroom, complete safe closure or truthful retained outcome and relevant negatives. Observer unavailability/inconclusive backlog/unknown kernel maximum yields NOT_QUALIFIED, never timeout PASS. Runtime tests and E1-E12 are NOT_EXECUTED here; this recipe does not authorize a new wire or upstream change.
