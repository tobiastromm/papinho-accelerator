## Candidate admission evidence and recommendation

The isolated x64 allocator model executes known-envelope/identity/overflow checks before modeled external effects, allocates/touches fixed slabs, and preserves credits in a terminal-retained slot. Tests cover stale generation, same-Session early reuse, unknown envelope, forged size, retained eviction, no reclamation from Stop/attempt, callback quiescence, and exactly-once eligible destruction. CANCEL/FINAL reserved bytes remain accessible with DATA spans filled.

Accelerator model two core512KiB operations plus two16KiB Sessions consumes1081344 managed bytes. Browser model one512KiB core plus1MiB app plus16KiB Session consumes1589248; a second such operation is denied by the2MiB cap. These are real allocations of candidate-model storage, not real Browser/C2 production admission. Synthetic retained slabs survive until explicit diagnostic process containment; exit is not clean teardown or quota recovery.

Policy remains: reserve bounded slots/bytes/CONTROL/CANCEL/FINAL/callback/lease/kernel allowances before effects; include retained lifetimes; preserve first cause and immutable identity; deny unknown mandatory hard-bound categories; no destructive eviction, fallback or reconnect bypass. CONTROL-first bounded fairness remains a proposed scheduler obligation, not tested production behavior.
